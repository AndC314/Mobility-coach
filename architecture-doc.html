3.2 Firestore Sync Architecture

src/hooks/useFirebaseSync.ts (833 lines)

Bidirectional sync uses two mechanisms running concurrently:

DirectionMechanismTrigger
Firestore → LocalonSnapshot listeners (8 collections)Real-time, continuous while logged in
Local → FirestorecatchUpSync() pushOnce on login (pushes local-only records)
Local → FirestoreaddDoc callbacks on log creationImmediately on each new log entry

Firestore document path pattern: users/{uid}/{collection}/{docId}

AI coaching path: users/{uid}/aiCoaching/{section}_{YYYY-MM-DD}

Key constraint: Firestore rejects undefined values. All writes pass through stripUndefined() helper before addDoc().

5. Mathematical Models

5.1 Supercompensation (Banister Two-Factor)

src/lib/supercompensation.ts

P(t) = P₀ + Σ[ k₁·wᵢ·exp(-(t-tᵢ)/τ₁) ] - Σ[ k₂·wᵢ·exp(-(t-tᵢ)/τ₂) ]

Category Parameters:
  Strength   → τ₁=21, τ₂=3,   k₁=1, k₂=2.2
  Grappling  → τ₁=25, τ₂=4,   k₁=1, k₂=2.0
  Mobility   → τ₁=30, τ₂=1.5, k₁=1, k₂=1.8

Training Impulse:
  impulse = BASE_IMPULSE(8) × intensity × density_factor
  intensity = session_volume / running_best_volume
  density = 1 + (exercise_count - 1) × 0.1

Atrophy (no training > 10 days):
  P(t) = baseline × exp(-0.4 × (days_inactive - 10))
  Floor = 70, Baseline = 100

5.2 Training Hours Consistency

src/lib/trainingHourCalculator.ts

active_hours = total_hours × (1 - 0.05 × weeks_inactive)
Decay: 5% per week of inactivity → Floor: 0h

5.3 Session Recommendation (Rule-Based)

src/lib/calisthenicsSession.ts & src/lib/recommendation.ts

priority = (100 - supercomp_score) + recency_bonus + plateau_penalty
recency_bonus = min(days_since_last × 3, 30)
Micro-progression: +1 set at a time, max +10% weekly volume
Deload: every 4th week (reduce volume 40-50%)

Rate limits (free tier): 15 RPM, 250K TPM, 500 RPD

Fallback: On 429, returns friendly "bots fixing bugs" message with rateLimited: true flag.

9. PWA & Offline

  • Service Worker: Workbox (via VitePWA plugin) with cache-first strategy
  • Manifest: Installable on iOS/Android, standalone display mode
  • Offline data: Full app works without network — Dexie stores everything locally
  • Wake Lock: useWakeLock hook keeps screen on during active timers
  • Audio: Completion dings via Web Audio API (primed on user interaction)
